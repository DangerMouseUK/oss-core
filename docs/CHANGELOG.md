# Changelog and API notes

For consumers of `oss-core` (oss-server, oss-client, bots, tools). Newest first. Crates are pre-1.0: names may still change, but changes are listed here.

## Unreleased

### oss-net (OpenSec speed)
- At 500 players OpenSec now costs 5.3% of a core instead of 11.5% (336 instead of 738 ns per packet). The cause was the x86 backend choice of the `poly1305` dependency: its run-time AVX2 path is about three times slower than its portable backend for game-sized records. The portable backend is selected with `--cfg poly1305_backend="soft"`.
- This repository now sets that flag on x86 in `.cargo/config.toml`. Servers built from other repositories must set it themselves, or build with `-C target-cpu=x86-64-v3`.
- Measurements, the remaining floor (about 0.3 µs for a small record, 1 µs for a full one) and operator guidance are in `docs/performance.md`, section "OpenSec". `cargo bench -p oss-net -- opensec` gains seal and seal+open benchmarks.

### Docs
- `docs/protocol/verification.md` records the evidence behind every packet, transport behaviour, checksum and file format. Each item is at one of four levels:
  - **vectors**: checked byte for byte against an unmodified reference implementation;
  - **sources**: agrees with the reference server and at least one other source;
  - **partly inferred**: the fields of unknown meaning are named;
  - **project spec**.
- Every protocol and format page links to it.
- The packet tables already covered every implemented packet. Writing this page also resolved a naming conflict: S2C `0x1A` is a score reset (the client handler table and Subspace Server .NET), although ASSS names the constant `TIMEDGAME`.

### oss-conformance (new crate, MIT)
- A conformance suite any implementation can run (`docs/conformance.md`). The `oss-conformance` binary has three modes:
  - `vectors`: 3,725 offline checks from the published vectors, run through a line-based stdin/stdout adapter written in any language. They cover VIE, the exe/position/settings/map checksums, the settings layout of 1,692 keys, OpenSec, canonical encodings of every S2C/C2S/core packet, and relay frames.
  - `server HOST:PORT`: live checks of a server's transport, login, arena entry, map download and security exchange.
  - `client --bind ADDR`: live checks of a connecting client: login, acknowledgements, arena entry, map download, position checksums, time sync and security checksums.
- `oss-conformance adapter` serves the reference adapter. The library exposes `adapter::run`, `live::check_server` and `live::check_client`.
- Results: oss-core passes every vector; `oss-bot-sdk` passes the client checks; `oss-server` passes the server checks (one is skipped because it sent no security request).
- The vectors are embedded copies, tested against their sources:
  - `packets.txt` is generated from oss-proto's round-trip samples;
  - the synthetic map files are generated by oss-formats' tests;
  - both are refreshed with `OSS_REGEN_VECTORS=1`.

### oss-net
- `opensec::{seal_record, open_record, Direction}` seal and open single records at an explicit counter, for tests and interoperability.
- `opensec` re-exports `PublicKey` and `StaticSecret`, used by `server_respond` and `client_finish`.

### oss-net (performance)
- `examples/soak.rs` is a load and soak harness. It drives hundreds of simulated players through one `Server` with configurable loss, latency, jitter, position fan-out, reliable chat and churn, and reports server CPU, cost per packet, throughput, server heap and reliable delivery. Runs are reproducible.
  - Results and method: `docs/performance.md`.
  - With VIE, 500 players take about 3% of a core; with OpenSec, about 12%.
  - CI runs it with `--max-cpu 20`.
- Fixed per-packet allocations under load: the server's shared buffer pool was capped at 256 buffers. It now scales with the connection count, and connections are topped up to 16 buffers. At 500 players, allocations fell from about 27,700 to about 30 per second.
- New `Connection::queued_reliable()`: the reliable backlog (waiting plus unacknowledged), for back-pressure and metrics.

### oss-proto (breaking)
- `c2s::Rebroadcast`: the embedded packet is now private and never empty.
  - Build one with `Rebroadcast::new(target, packet) -> Option<Self>`, which returns `None` for an empty packet.
  - Read it with `packet()` or `into_packet()`.
  - `Default` is gone.
- Before this change an empty rebroadcast encoded to 3 bytes that decoding rejects. Now the encoder and decoder agree on every value, and the property test that found the mismatch still runs.

### oss-proto (property tests)
- Every packet now round-trips over arbitrary field values, tested with proptest (a dev-dependency only). Covered:
  - all S2C and C2S packets: 20,000 cases each;
  - core `0x00` packets: 20,000 cases;
  - billing and directory packets;
  - typed `Packet` impls, including the boxed ones.
- Fixed-layout packets get their generators from the packet macros. A compile-time exhaustive `match` plus a coverage test make sure every enum variant is generated.
- Constraint the tests surfaced: C2S `0x0A` (rebroadcast) must carry a non-empty inner packet. An empty one encodes to 3 bytes that the decoder rejects.

### oss-bot-sdk (new crate, MIT)
- A small layer over `oss-net` and `oss-proto` that turns a bot into one file. See the crate README and `examples/greeter.rs`, which greets players and answers `!ping`.
- `Session` is the sans-IO core. It handles:
  - connecting, with `Encryption::{Vie, OpenSec, OpenSecOrVie}`;
  - logging in, creating the account if the name is new;
  - entering an arena, then switching to the configured ship;
  - keeping the player list (`players`, `player`, `player_by_name`);
  - sending position updates;
  - answering security checks (settings, exe and map checksums, downloading the map once per arena).
- Events (`BotEvent`): `Connected`, `LoggedIn`, `LoginFailed`, `EnteredArena`, `PlayerEntered { player, initial }`, `PlayerLeft`, `Chat(ChatMessage)`, `Position`, `Kill`, `ShipChanged`, `FreqChanged`, `Packet` (anything else) and `Disconnected`.
  - Remote private messages are parsed into a sender and the text.
- Actions:
  - chat: `send_public`, `send_team`, `send_private`, `send_private_to` (in-arena or remote) and `reply`;
  - ship, team and arena: `set_ship`, `set_freq` and `go_arena`;
  - movement: `set_position` and `send_position_now`;
  - anything else: `send_packet` and `disconnect`.
- `run(addr, config, &mut handler)` is a blocking UDP loop. Closures `FnMut(&mut Session, BotEvent)` work as handlers.
- Tested against a scripted in-process zone. The greeter example was also run against the real `oss-server`: two bots logged in and entered the arena.

### oss-net (browsers)
- All three crates build for `wasm32-unknown-unknown` with default features. On that target, `os-entropy` takes its randomness from the browser's Web Crypto API (getrandom's `wasm_js` backend), so OpenSec works in browsers without extra setup.
- CI builds and lints the wasm target for every crate, and builds `oss-net` without features.
- New `relay` module: the `oss-relay.1` WebSocket relay framing for browser clients (spec in `docs/protocol/websocket-relay.md`).
  - `Frame` covers `Datagram`, `Hello`, `Welcome` and `Close`, with `decode` and `encode`, and `CloseReason`.
  - For byte streams: `StreamDecoder` (`push`, `next_frame`, `buffered`, `is_broken`) and `write_stream_frame`.
  - The codec is sans-IO and has a fuzz target, `net_relay`.

### Fuzzing
- `fuzz/`: cargo-fuzz targets for every decoder and for the transport, kept out of the workspace build (CI only checks that they compile). See `fuzz/README.md`.
  - Decoders: all C2S/S2C packets, core `0x00` packets, billing and directory packets, `.lvl`/eLVL, region bitmaps, `.lvz`, `.ossr`.
  - Transport: `Server` and an established client `Connection` fed arbitrary datagrams, interleaved with sends, big and sized transfers, and disconnects.
  - Ciphers: VIE with arbitrary keys; OpenSec records checked against a reference replay window, plus both handshakes.
  - Besides "no panic", targets check that decoded values re-encode to the same value and that no datagram exceeds `max_send`.
- Four minutes per target found no crashes, hangs or invariant failures. One harness finding: decoding a position or weapon packet keeps the received checksum, while encoding always writes a fresh one. That is intended, and now documented in the targets.

### Packaging
- crates.io-ready metadata for each crate: keywords, categories, homepage and documentation links, a README (its example compiles as a doctest), a LICENSE file, and docs.rs `all-features` for `oss-net`.
- `cargo package --workspace` passes.
- CI gains three jobs:
  - feature combinations and wasm32 checks;
  - an MSRV (1.88) check;
  - a packaging check.

### oss-net (OpenSec)
- `opensec` module, behind the default feature `opensec`. Specification: `docs/protocol/opensec.md`; vectors: `tests/vectors/opensec.txt`.
  - Server side: `OpenSecAcceptor::new(Option<ServerKey>, Entropy)`; `ServerKey` provides `from_secret`, `generate`, `public` and `secret_bytes`.
  - Client side: `OpenSecClientHandshake::new(&Entropy, pinned: Option<[u8; 32]>)` plus `.timeout(ms)`.
  - Also exposed: `OpenSecCipher` and the pure functions `server_respond` and `client_finish`.
  - Entropy: `os_entropy()` behind the feature `os-entropy`. Without that feature (e.g. for wasm), supply your own `Entropy`.
- `cipher::Fallback::new(primary, secondary, switch_after_ms)` switches handshakes when the primary gets no answer, for example OpenSec then VIE. A primary *failure* never falls back.
- New `Cipher` trait methods, both with defaults: `overhead()` (the connection shrinks packing to fit) and `peer_key()`. New `Connection::peer_key()` and `CipherKind::OpenSec`.
- `Server` now answers an exact duplicate of a connection request from a fresh connection by resending its cached reply, instead of re-keying.
- `oss-net` builds for `wasm32-unknown-unknown` with `--no-default-features --features opensec`.

### oss-formats (replay)
- `replay`: `.ossr` replay files.
  - Types: `Replay { records, truncated }` and `Record { kind: RecordKind, time_ms, data }`.
  - Record kinds: `Meta`, `ServerPacket`, `ClientPacket`, `File`, `Marker`, `Other(u8)`.
  - Reading: `Replay::parse` handles plain or zlib bodies and tolerates truncation. Helpers: `meta_value`, `files`, `duration_ms`, `seek`.
  - Writing: `to_bytes(compress)`. A streaming recorder uses `header(flags)` and `write_record(..)`.
- Docs: `docs/formats/replay.md`.

### oss-proto (directory, billing)
- `directory`: `ZoneUpdate` (server registration datagram, with an `is_acceptable()` check that mirrors directory servers), `DirPing`/`DirPong`, `ZoneListRequest`, `ZoneList`/`ZoneEntry`. Default ports `CLIENT_PORT` (4990) and `UPDATE_PORT` (4991).
- `billing`: `ServerToBiller` and `BillerToServer` enums covering every documented packet, plus `UserLogin`, `BillerLogin`, `PlayerScore` and the `login_result` codes. Each enum has `decode`, `encode` and `to_bytes`, with `Unknown` as the fallback.
- Docs: `docs/protocol/directory.md`, `docs/protocol/billing.md`.

### oss-net (send options)
- `Connection::send_with(&[u8], SendFlags)` and `Server::send_with`. `SendFlags { reliable, priority: Priority::{Low, Normal, High, Urgent}, droppable }`, plus the constants `SendFlags::RELIABLE` and `UNRELIABLE`.
  - Unreliable packets flush in priority order.
  - `Urgent` is sent at once in its own datagram.
- `Config::unreliable_budget: Option<usize>` caps unreliable bytes per flush. When the budget runs out, droppable packets are discarded (counted in `Stats::dropped_outgoing`) and the rest wait for the next flush. `send(p, reliable)` is unchanged.

### Map vectors, deny
- Synthetic map-checksum vectors run in CI with no binary fixtures: `tests/synthetic_maps.rs` regenerates the four seeded maps (verified against the recorded size and CRC-32). `smallmap.lvl`, the reference server's default map, is a committed fixture with its 33 vectors.
- **Behaviour change:** `Level::to_bytes` no longer pads the tileset before the eLVL section, so files whose metadata starts at an unaligned offset rewrite byte for byte. For new files, build the tileset with `Tileset::from_bitmap(&bmp)`, which pads to 4 bytes.
- `deny.toml`: `unmaintained = "workspace"`.

### Reference vectors (compiled C)
- Test fixtures are now generated by running the unmodified reference implementations. They cover:
  - VIE key exchange, tables and per-packet crypto: 16 keys, 1,584 records (`oss-net/tests/vectors`);
  - position, settings and VIE exe checksums, and both settings packets with every field's bit offset (`oss-proto/tests/vectors`);
  - map checksums (`oss-formats/tests/vectors`; env-gated because the maps are not committed).

  All of them match.
- **Behaviour change:** `checksum::map_checksum` now wraps coordinates modulo 1024, as the reference server does for keys ≥ `0x80000000`. The closure always receives 0..1024.
- New `Level::server_tile_grid() -> (TileGrid, GridStats)` expands big objects: large asteroid 2×2, wormhole 5×5, space station 6×6. Use it for the map checksum. Tile number constants are in `lvl::tile`.

### oss-net (hot path, cipher kind)
- `Connection::recycle(Vec<u8>)` and `Server::recycle(Vec<u8>)` return buffers from `poll_transmit` and `Event::Packet` for reuse. When callers recycle, a connected `Connection`/`Server` performs **zero heap allocations per packet** in steady state, enforced by `tests/alloc_free.rs`.
- Internals: pooled buffers, a ring buffer for reliable receive, and clusters packed straight into the outgoing datagram.
- VIE encryption is about 20× faster (155 ns per 512-byte packet).
- `cargo bench -p oss-net --bench transport` (criterion) measures VIE encrypt/decrypt, a reliable 64-byte round trip, and a 20-packet cluster pass.
- `Cipher::kind() -> CipherKind { None, Vie, Continuum, Other }`, with a default of `Other`. External ciphers should override it.
- `Connection::cipher_kind() -> Option<CipherKind>`.
- `Connection::connect_protocol() -> Option<u16>` returns the protocol word from the client's `00 01` (0x0001 SubSpace, 0x0011 Continuum) on server-side connections. Use it, or `cipher_kind`, for the login length check.

### oss-net
- `Connection` (either end, sans-IO):
  - Construction: `client(cfg, Box<dyn Handshake>, now)`, `server(cfg, Accept, now)`.
  - Driving: `handle_datagram`, `tick`, `flush`, `send(&[u8], reliable)` (anything over 506 bytes goes as reliable big data), `send_sized` / `cancel_outgoing_sized` / `cancel_incoming_sized`, `disconnect`.
  - Output: `poll_transmit`, and `poll_event` returning `Event::{Connected, Packet, SizedProgress, SizedIncomingCancelled, SizedSent, SizedCancelled, Disconnected}`.
  - Status: `stats`, `rtt_ms`, `server_ticks(now)`, `peer_counts`, `next_timeout`.
  - `Config::{client, server}` expose public tunables; `ticks(now_ms)` converts to protocol ticks.
- `Server<A>`: `new`, `add_acceptor`, `max_connections`, `handle_datagram(now, addr, &[u8])`, `tick`, `send`, `connection(_mut)`, `disconnect`, `poll_transmit -> (A, Vec<u8>)`, `poll_event -> (A, Event)`.
- `cipher`:
  - Traits: object-safe `Cipher` (including `handle_core` for in-session subtypes ≥ 0x10, and `poll`), `Handshake`, `Acceptor`.
  - Supporting types: `Accept`, `Step`, `CipherContext`.
  - Implementations and helpers: `NullCipher`, `VieAcceptor`, `NullAcceptor`, `VieClientHandshake`, `vie_cipher`, `parse_connect`.
- `vie`: `VieCipher`, `client_key_from_seed`, `server_key_for`.

### oss-proto (rng)
- `VieRng`: the shared prize/door generator, with `new(seed)` and `next_u32()`; it also implements `Iterator`.

### docs
- `docs/protocol/` adds pages on transport, encryption, game packets, settings and checksums.

### oss-formats
- `Level::parse(&[u8]) -> Result<Level, FormatError>` / `Level::to_bytes()`: `.lvl` files with optional tileset (`Tileset { bytes }`, raw BMP incl. file header), optional eLVL `Metadata`, `tiles: Vec<TileEntry>` in file order. Well-formed files rewrite byte for byte.
- `Level::tile_grid() -> TileGrid` (dense 1024x1024, `get(x, y)`, `set`, `cells()`); `Level::set_tiles_from_grid`.
- `Metadata { reserved, chunks: Vec<Chunk> }`; `Chunk::{Attribute, Region, TileData, Other}`; helpers `attribute(key)`, `attributes()`, `regions()`.
- `Region { chunks: Vec<RegionChunk> }`, `RegionChunk::{Name, Tiles, Base, NoAntiwarp, NoWeapons, NoFlagDrops, AutoWarp, Code, Other}`; helpers `name()`, `tiles() -> RegionBitmap`, `is_base()`, `no_antiwarp()`, `no_weapons()`, `no_flag_drops()`, `auto_warp()`.
- `RegionBitmap` (1 bit per tile): `contains`, `set`, `iter`, `count`, `decode(rTIL bytes)`, `encode()`.
- Crate is `no_std` + `alloc`.

### oss-proto
- `ClientSettings` (S2C `0x0F`, 1428 bytes): wire-shaped arrays (`bits`, `ships: [ShipSettings; 8]`, `longs`, `spawns: [SpawnPosition; 4]`, `shorts`, `bytes`, `prize_weights`) with named getters/setters (`ships[i].maximum_speed()`, `set_radius(..)`, `door_mode()`, ...). `decode(&[u8])`, `encode(&mut Vec<u8>)`, `to_bytes()`; exact for every byte.
- Config-name tables for servers filling settings generically: `SHIP_NAMES`, `LONG_KEYS` (+ `LONG_KEYS_X1000`), `SHORT_KEYS`, `BYTE_KEYS`, `PRIZE_WEIGHT_KEYS`, `SHIP_LONG_KEYS`, `SHIP_SHORT_KEYS`, `SHIP_BYTE_KEYS`, bitfield tables `ARENA_BITS`, `SHIP_MISC_BITS`, `SHIP_WEAPON_BITS` (`(key, lo, width)`), helpers `get_bits`/`set_bits`.
- `checksum`: `crc32`, `crc32_update`, `position_checksum`, `settings_checksum(key, &packet_bytes)`, `map_checksum(key, |x, y| tile)`, `map_crc32(&grid_cells)`, `vie_exe_checksum(key)`.
- `wire::{Reader, Writer}`, `FixedStr<N>` (NUL-padded text fields, raw bytes preserved).
- Crate is `no_std` + `alloc`.

### oss-formats (lvz)
- `Lvz::parse` / `to_bytes` (byte-exact; compressed bytes kept as stored), `Section { name, file_time, decompressed_size, stored }`, `Section::data()` (inflate), `Section::new(name, time, data)` (deflate), `Section::objects(&ObjectSection)`, `Lvz::object_sections()`.
- `ObjectSection { version, objects: Vec<ObjectData>, images: Vec<ImageDef> }`. `ObjectData` is `oss_proto::ObjectData` (re-exported), with accessors for map/screen coordinates, layer, mode, display time.
- New dependencies: `oss-proto`, `miniz_oxide` 0.8 (MIT/Zlib/Apache-2.0, `no_std` + alloc).

### oss-proto (game packets)
- `s2c` and `c2s` modules: a struct per packet type implementing `Packet` (`TYPE`, `decode(&[u8])` with type byte, `encode`, `to_bytes`), type-byte constants in `s2c::kind` / `c2s::kind`, and dispatch enums `S2CPacket` / `C2SPacket` (`decode`, `encode`, `to_bytes`, `kind()`, `From<T>` for each packet, `Unknown { kind, data }` fallback). `Settings` and `Registration` variants are boxed.
- Multi-length packets: `PlayerId.extra`, `SpecData::{ExtraData, Player}`, `MapFilename::{Single, Files}`, `GoArena.optional_graphics` (26/27), `Login` (101/165; `ContLogin` wraps the 0x24 form), `MapRequest.index`, `SecurityResponse.continuum` (40/46), `Bricks` (empty = clear).
- **Breaking:** S2C position packets now carry `tail: PositionTail { None, Energy(u16), Extra(ExtraPositionData) }` (lengths 16/18/26 and 21/23/31) instead of `extra: Option<_>`.
- Shared structures in `common`: `PlayerData` (64-byte S2C 0x03 records, concatenatable), `Brick`, `DamageData`, `ObjectToggle`, `ObjectChange`, `SmallBatchedPosition` / `LargeBatchedPosition` / `PackedMotion` (0x39/0x3A), constants `chat_type`, `prize`, `object_change`; `c2s::client_features`, `c2s::arena_type`, `s2c::login_code`.
- `wire::Raw<N>` for long raw byte fields (banners).
