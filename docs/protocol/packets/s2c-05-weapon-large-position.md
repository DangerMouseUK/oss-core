## Layout

| Offset | Size | Type | Field | Meaning |
|---|---|---|---|---|
| 0 | 1 | u8 | type | `0x05` |
| 1 | 1 | i8 | rotation | 0–39 |
| 2 | 2 | u16 | time | Low 16 bits of the server time (ticks) |
| 4 | 2 | i16 | x | Pixels |
| 6 | 2 | i16 | y_speed |  |
| 8 | 2 | u16 | player_id |  |
| 10 | 2 | i16 | x_speed |  |
| 12 | 1 | u8 | checksum | XOR of bytes 0–20 with this byte taken as 0 |
| 13 | 1 | u8 | status | Status bits |
| 14 | 1 | u8 | c2s_latency | Ticks |
| 15 | 2 | i16 | y | Pixels |
| 17 | 2 | u16 | bounty |  |
| 19 | 2 | u16 | weapon | Weapon word |
| 21 | 0, 2 or 10 | tail | tail | Nothing, energy (`u16`), or extra position data |

Integers are little-endian. `n` is a variable length; `i` counts repeated entries from 0.

## Notes

Servers use this form when a weapon was fired or the pid or bounty does not fit in a byte; otherwise `0x28`. The tail is chosen per recipient.
